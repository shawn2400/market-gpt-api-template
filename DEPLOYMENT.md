## 🎯 Overview

AlgoGPT is a 24/7 algorithmic trading platform designed for Binance Futures trading with:
- **Multi-Timeframe Analysis** (15M/1H/4H)
- **AI-Powered Decisions** (GPT-4)
- **GRID Trading** for sideways markets
- **FUTURES Trading** for trending markets
- **Telegram Approval System**

## ✅ Prerequisites

Before deploying, ensure you have:

1. **GitHub Account** with AlgoGPT repository
2. **Render.com Account** (linked to GitHub)
3. **API Keys**:
   - Binance API Key + Secret (Futures enabled)
   - OpenAI API Key (GPT-4 access)
   - Telegram Bot Token
   - Telegram Chat ID

4. **PostgreSQL Database** (provided by Render.com)

### Required Secrets (Add in Render.com Dashboard)

```bash

BINANCE_API_SECRET=your_binance_secret

# OpenAI

# Telegram
TELEGRAM_BOT_TOKEN=1234567890:ABCdefGHI...
TELEGRAM_CHAT_ID=123456789
TELEGRAM_ADMIN_IDS=123456789

# Database (Auto-generated by Render.com)

# Security
OPS_SIGN_SECRET=generate_random_64_char_secret
WEBHOOK_HMAC_SECRET=generate_random_64_char_secret

# Public Host (Update after deployment)
PUBLIC_HOST=https://algogpt-prod.onrender.com
```

### Optional Configuration

```bash
# Trading Modes
AUTO_RUN=1                    # Enable automated trading
EXECUTE_TRADES=1              # Actually execute trades
TRADE_AUTO_SUGGEST=1          # Enable auto-suggestions
SUGGEST_FUTURES=1             # Enable FUTURES proposals
SUGGEST_GRID=1                # Enable GRID proposals

# Multi-Timeframe Analysis
USE_MULTI_TF=1                # Enable 15M/1H/4H analysis

# Logging
LOG_LEVEL=INFO                # DEBUG/INFO/WARNING/ERROR

# Workers
SUGGEST_INTERVAL_SEC=60       # Scan interval in seconds
POSITION_REPORT_INTERVAL_SEC=1800  # Position monitoring interval
```

## 🚀 Deployment to Render.com

### Step 1: Push Code to GitHub

```bash
# Verify your changes
git status

# Commit changes (Replit auto-commits)
# Changes already committed by Replit system

# Push to GitHub
git push origin main
```

### Step 2: Create New Web Service on Render.com

1. **Login to Render.com** → Dashboard
2. **Click "New +"** → "Web Service"
3. **Connect Repository**: Select your AlgoGPT GitHub repo
4. **Configure Service**:
   - **Name**: `algogpt-prod`
   - **Region**: Frankfurt (closest to Binance servers)
   - **Branch**: `main`
   - **Root Directory**: `.` (project root)
   - **Environment**: `Docker`
   - **Dockerfile Path**: `./Dockerfile`
   - **Plan**: Standard (or higher)

### Step 3: Configure Build & Deploy

**Build Command**: (Leave empty - Docker handles this)

**Start Command**: (Leave empty - Dockerfile CMD handles this)

**Health Check Path**: `/readyz`

### Step 4: Add Environment Variables

In the Render.com dashboard:
1. Go to "Environment" tab
2. Add all required secrets from above
3. Click "Save Changes"

### Step 5: Add PostgreSQL Database

1. Click "New +" → "PostgreSQL"
2. Name: `algogpt-db`
3. Link to your web service
4. Render will auto-populate `DATABASE_URL`

### Step 6: Add Persistent Disk

1. In web service settings, go to "Disks"
2. Add disk:
   - **Name**: `data`
   - **Mount Path**: `/app/data`
   - **Size**: 1 GB

### Step 7: Deploy!

1. Click "Manual Deploy" → "Deploy latest commit"
2. Monitor build logs
3. Wait for deployment to complete (~5-10 minutes)

### Step 8: Update PUBLIC_HOST

After deployment completes:
1. Copy your service URL (e.g., `https://algogpt-prod.onrender.com`)
2. Update `PUBLIC_HOST` environment variable
3. Redeploy for changes to take effect

## 🔧 Troubleshooting

### Issue: "Container failed to start"

**Solution**: Check Dockerfile syntax and build logs in Render.com

### Issue: "Health check failing"

**Possible causes**:
1. Port mismatch (ensure PORT=10000 in render.yaml)
2. Application not starting (check logs)
3. Database connection issues (verify DATABASE_URL)

**Fix**:
```bash
# Test locally with Docker
docker build -t algogpt .
docker run -p 10000:10000 --env-file .env algogpt
curl http://localhost:10000/readyz
```

### Issue: "No trade proposals"

**This is NORMAL** if:
- Market is CHOPPY/NEUTRAL/MIXED (system prefers GRID)
- GPT-4 confidence is low (<30%)
- RR ratio doesn't meet minimum threshold

**Check**:
1. Logs show: `Multi-TF Analysis: CHOPPY | NEUTRAL | Vol:medium`
2. AI responses: `NO PROPOSAL from AI for SYMBOL`
3. GRID proposals being generated instead

**Solution**: Wait for better market conditions or adjust dynamic filters.

### Issue: "FUTURES proposals always rejected"

**Expected behavior** when:
- Market regime: CHOPPY/SIDEWAYS
- Mood: NEUTRAL
- TF-Alignment: mixed/weak

**Solution**: System will automatically switch to FUTURES when:
- Market regime: TRENDING
- Mood: BULLISH/BEARISH
- TF-Alignment: strong/moderate

### Issue: "NoneType comparison errors"

**Status**: ✅ FIXED in latest commit

All None-handling bugs in `utils/market_intelligence.py` have been resolved using the pattern:
```python
value = ctx.get("key") or default_value
```

### Issue: "BAD SIG - Invalid signature"

**Cause**: Telegram callback signature mismatch

**Solution**:
1. Verify `OPS_SIGN_SECRET` is set correctly
2. Check comprehensive debug logs in Telegram callbacks
3. Ensure webhook timestamps are within valid window

## 📊 Monitoring

### Key Metrics to Monitor

1. **Response Time**: Health check should respond <2s
2. **Memory Usage**: Should stay <512MB for Standard plan
3. **CPU Usage**: Should stay <50% average
4. **Database Connections**: Monitor PostgreSQL connection pool

### Performance Optimization

1. **Reduce scan interval** if too many API calls:
   ```bash
   SUGGEST_INTERVAL_SEC=120  # Increase from 60 to 120
   ```

2. **Disable unused features**:
   ```bash
   SUGGEST_FUTURES=0  # Disable if only using GRID
   ```

3. **Adjust worker count**:
   ```bash
   WEB_CONCURRENCY=2  # Increase if handling high traffic
   ```
