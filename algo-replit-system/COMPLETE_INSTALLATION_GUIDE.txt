CONFIGURATION (.env file):
============================

Generated automatically, customize as needed:

  ADMIN_TOKEN=your_secure_token_here
    → Change this! Used for all authentication

  ENABLE_SCALE_MODE=false
    → Set to true to activate multi-user features

  OLLAMA_MODEL=llama2
    → Options: llama2 (default), mistral, codellama

  POSTGRES_PASSWORD=change_me_in_production
    → Secure database password

  LOG_LEVEL=INFO
    → Options: DEBUG, INFO, WARNING, ERROR

TROUBLESHOOTING:
=================

Services won't start?
  docker-compose logs -f core-control-server

Out of memory?
  docker-compose stats
  (Increase Docker memory limits)

AI not responding?
  docker-compose logs ollama
  docker-compose exec ollama ollama pull llama2

Database error?
  docker-compose logs postgres
  (Check PostgreSQL is running)

Files not saving?
  Check disk space: df -h
  Check permissions: ls -la /workspaces

Can't access dashboard?
  Check API: curl http://localhost:8001/health
  Check frontend: docker-compose logs core-control-server

PRODUCTION TIPS:
=================

Before using in production:

1. Change ADMIN_TOKEN in .env
   openssl rand -hex 32

2. Change POSTGRES_PASSWORD
   openssl rand -hex 32

3. Disable debug logging
   LOG_LEVEL=INFO (not DEBUG)

4. Set up SSL/TLS
   Use nginx reverse proxy in front

5. Regular backups
   Automatic every 24h, kept 7 days

6. Monitor resources
   CPU/memory alerts recommended

7. Update Docker images
   docker-compose pull
   docker-compose up -d

SCALING TO MULTI-USER:
=======================

When you need multi-user features:

1. Edit .env file
   ENABLE_SCALE_MODE=true

2. Restart system
   docker-compose down
   docker-compose up -d

3. Features activated:
   ✓ Multi-user isolation
   ✓ Wallet separation
   ✓ Load balancing
   ✓ Permission tiers
   ✓ API per-user keys

4. Add more users
   API: POST /users/create

5. For multiple servers
   Use Kubernetes or Docker Swarm
