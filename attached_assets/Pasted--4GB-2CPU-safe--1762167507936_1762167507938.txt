## דרישות עומס/ביצועים (קשיח)

**משאבים כוללים (שרת 4GB/2CPU):**

* מקסימום **Concurrency עיבוד ליבה**: `8` (async workers).
* מקסימום **Jobs כבדים** במקביל (Backtests/Scenario/Correlation): `2` (בתור בלבד).
* תקציב זיכרון ליישום: ≤ **3.2GB** בפועל; Guard: הורד פיצ’רים אם RSS ≥ **3.4GB**.

**SSE / רשת:**

* SSE batching: **כל 3–5s** (ללא פושים לכל אירוע).
* חיבורי SSE סימולטניים: ≤ **50**. מעבר ל-50 ⇒ fallback ל-polling 5s.
* Heartbeat SSE כל **15s**.

**קאשינג/דאטה:**

* **AI Semantic Cache-Hit ≥ 90%** לשאלות חוזרות. TTL דינמי: 10–60 דק׳.
* קאש סימבולים/סטֵיט: TTL **15–45s**; only **Top-K=20** סימבולים חמים.
* חיפושי טבלה: ≤ **100ms** עד 10k רשומות (client-side virtualized).

**AI עלויות/ניתוב:**

* תקציב יומי AI: **$8** (ברירת מחדל), חודשי: **$180**. התראה ב-80%, Auto-Pause ב-100%.
* ניתוב:

  * שאילתא **פשוטה/קצרה** → **DeepSeek** (זול).
  * מורכבת/החלטת מסחר/דוח → **GPT-5**.
  * אימות/השוואה נקודתית → **AI-X/Grok**.
* p95 תשובת צ׳אט: < **2s** (שאילתות non-stream).

**בורסות/Rate Limits:**

* פרופילים: **Safe / Normal / Aggressive**. ברירת מחדל: **Normal**.
* מעבר אוטומטי ל-Safe אם מקבלים **429** או p95 API > **800ms**.
* חזרתיות (Retry) עם **exponential backoff + jitter**: 250→500→1000ms (מקס׳ 3 נסיונות).
* Router: Fallback עד **2** מקומות (venues) עם **Idempotency**.

**טריידים/ניהול:**

* מקסימום טריידים מנוהלים במקביל: **12**.
* **No-Chase > 0.3%**; Fill-Prob gate ≥ **0.62**.
* **VaR-Live 0.8–1.2%** לטרייד; **Daily Loss Cap 2–3%**; **Kelly-Lite ≤ 0.5×**.
* Flip **A+ בלבד**; Grid = פי **3** עומס בתור־עדיפות נפרד.

**דשבורד/Frontend:**

* **LCP < 2.0s**, **TTI < 3.0s**, bundle ≤ **250KB** gzip.
* תמונות: thumbnails 200/800px + lazy; וידאו: HLS 360/720 עם poster.
* CSP/HSTS + SameSite=Strict; RBAC: Admin/Viewer.

## Deliverables (מפתחי מערכת)

### A) Backend (חתום, RBAC)

1. **Global Execution Mode**

   * `GET /control/execution-mode` → `{ mode: "TELEGRAM" | "WEB_AUTO", updated_at, updated_by }`.
   * `POST /control/execution-mode` (Admin + HMAC+nonce+ts) → שינוי מצב.
   * **Cooldown 3s** בין שינויים; **Audit Trail** + `execution_mode.changed` ב-SSE.

2. **Enforcement ברמה מערכתית**

   * `TELEGRAM`: כל כרטיס כשיר → **Pending** לטלגרם; כפתורי אישור באתר כבויים.
   * `WEB_AUTO`: Auto-Executor מבצע כשירים **ללא אישור**; טלגרם **view-only**.
   * Gates/Policies תמיד פעילים (BTC-Gate, Quality≥Threshold, VaR, DailyCap, Kelly-Lite, No-Chase, Exposure/Correlation).

3. **Control Plane APIs (Ops)**

   * `POST /trade/ticket/prepare|execute|schedule` — תשובה כוללת `idempotency_key`/`audit_id`.
   * `POST /positions/{symbol}/manage` — SL→BE / Trail(ATR×N) / TP-Shift / Partial / Flip / Attach-Grid.
   * `POST /emergency/kill-switch` / `/economy-mode` / `/freeze-noncritical`.

4. **Load Guards**

   * Queue לכבדים (Backtest/Scenario/Correlation): מקס׳ **2** במקביל, FIFO עם עדיפות.
   * Memory watchdog: RSS>3.4GB ⇒ כבה פיצ’רים לא-קריטיים (גרפים/וידאו/אנימציות), עבור ל-Economy Mode.

5. **Observability**

   * p95/p99 per-route; queue depth; ratelimit hits; AI cost/decision; cache hit/miss; SSE uptime.
   * דו״ח יומי: **Core Guardian Report**.

### B) Frontend (Website)

1. **Toggle מרכזי (Header + Ops Tab)**

   * כיתוב: **“Execution Mode: Telegram Approvals / Web Auto”**.
   * סטטוס צבעוני: 🟦 Telegram (ברירת מחדל) / 🟩 Web Auto.
   * מעבר ל-Web Auto: **Double-Confirm** (סיסמה קצרה + checkbox אחריות).
   * SSE מציג שינוי מצב מיד (toast + קישור לרשומת Audit).

2. **Command & Control**

   * Quick Actions: Approve Next / Reject All / Place Prepared Ticket / Close All / Reduce 50% / Hedge Now / Flip A+ Only / Grid Start-Pause-Stop / Kill-Switch / Economy-Mode.
   * **Approvals Page**:

     * במצב Telegram — **read-only**.
     * במצב Web Auto — כפתורי Execute/Approve פעילים; בטלגרם view-only.

3. **ביצועים/אבטחה**

   * SSE batching 3–5s; עד 50 חיבורים; fallback ל-polling.
   * RBAC (Admin-only לשינויים), HMAC+nonce+ts בכל פעולה; CSRF+SameSite=Strict; WebAuthn אופציונלי.
