להדבקה לסוכן — גרסה מתוקנת: **ברירת מחדל = אישור דרך טלגרם**, וכפתור באתר שמחליף **דינמית** למצב **Web Auto (ללא טלגרם)**. לחיצה נוספת מחזירה ל“אישור בטלגרם”. הכל עם חתימות, RBAC, ו-Audit.

## **TASK NAME:** AlgoGPT — Super-Dashboard Control Switch (Telegram-Approve by Default → Web Auto Toggle)

**מטרה:**

1. ברירת מחדל: **כל הטריידים דורשים אישור בטלגרם** (Approve/Reject).
2. להוסיף באתר **כפתור מרכזי אחד** שמחליף בזמן אמת בין שני מצבים:

   * **Mode A — Telegram Approvals (Default):** כל הכרטיסים Pending עד אישור בטלגרם.
   * **Mode B — Web Auto (No Telegram):** ביצוע אוטומטי מלא מהאתר, ללא אישור ידני.

> המעבר דו-כיווני, מיידי, מאובטח, ומתועד. אין כפילות: בזמן Mode A — אין אישורים מהאתר; בזמן Mode B — טלגרם “צופה בלבד”.

---

### Deliverables — Backend (Core)

1. **Global Execution Mode API (חתום):**

   * `GET /control/execution-mode` → מחזיר `{ mode: "TELEGRAM" | "WEB_AUTO", updated_at, updated_by }`.
   * `POST /control/execution-mode` (HMAC+nonce+ts, Admin RBAC) עם גוף: `{ mode }`.
   * שינוי מצב כותב **Audit Trail** (מי/מתי/מאיפה/IP/חתימה) + **Event** ל-SSE.

2. **Router Enforcement:**

   * אם `mode=TELEGRAM`:

     * כל `trade_ticket` “כשיר” → נרשם ל־**Pending** ויוצא ל־Telegram בלבד; **חוסם** Execute מהאתר.
   * אם `mode=WEB_AUTO`:

     * `Auto-Executor` מבצע כרטיסים כשירים **ללא אישור**, וה־Telegram עובר ל־**view-only** (אין כפתורי אישור).
   * כל פקודת ביצוע בודקת מצב לפני פעולה (Source of Truth יחיד).

3. **Policy Gates נשמרים בשני המצבים:**

   * BTC-Gate, Quality≥Threshold, VaR-Live 0.8–1.2%, Daily Loss Cap 2–3%, Kelly-Lite ≤0.5×, No-Chase>0.3%, Exposure/Correlation Guards.
   * כישלון Gate → Pending עם **Reason** (בשני המצבים).

4. **Idempotency & Safety:**

   * `idempotency_key` לכל שינוי מצב/ביצוע.
   * **Cooldown 3 שנ׳** בין החלפות מצב למניעת “פינג-פונג”.
   * **Secret Rotation** ו־HMAC קיימים — לא משנים.

---

### Deliverables — Frontend (Site)

1. **Command Toggle (Header + Ops Tab):**

   * כפתור גדול: **“Execution Mode: Telegram Approvals / Web Auto”**.
   * סטטוס חי עם צבע:

     * 🟦 Telegram (Default) — “נדרש אישור בטלגרם”
     * 🟩 Web Auto — “ביצוע אוטומטי מהאתר”
   * **Double-Confirm** בעת מעבר ל-Web Auto: סיסמה קצרה + “אני מבין שזה ללא אישור ידני”.

2. **Behavior UI:**

   * במצב **Telegram**:

     * עמוד Approvals באתר מוצג **read-only** (“מנוהל דרך Telegram”).
     * כפתורי Execute/Approve באתר **כבויים**.
   * במצב **Web Auto**:

     * כפתורי Execute/Approve באתר **פעילים**; בטלגרם כפתורים נעלמים/מושבתים (“view-only”).
     * **Badge** ליד כל טרייד: “Auto-Executed via Web”.

3. **SSE Events:**

   * `execution_mode.changed` משתקף מיד ב-UI.
   * הודעת Toast מאשרת שינוי מצב + לינק ל-Audit Record.

4. **RBAC & Security:**

   * שינוי מצב: **Admin בלבד** (Replit Auth RBAC).
   * כל Action חתום (HMAC+nonce+ts), CSRF+SameSite=Strict, CSP/HSTS.
   * WebAuthn (אופציונלי) לעוד שכבת אישור בקפיצת מצב.

---

### Acceptance (PASS)

* ברירת מחדל אחרי Deploy: **mode=TELEGRAM**.
* מעבר ל-**WEB_AUTO** באתר → Auto-Executor מבצע כרטיס כשיר **ללא אישור**; בטלגרם אין כפתורי אישור.
* חזרה ל-**TELEGRAM** → האתר read-only לאישורים; אישורים פועלים בטלגרם בלבד.
* כל שינוי מצב רשום ב-Audit + מופיע ב-SSE; Cooldown מונע החלפות תכופות.
* Gates/Policies נאכפים בשני המצבים; כישלונות Gate מתועדים עם Reason.

---

### SLO Targets

* Toggle Mode (POST) → תגובה ≤ **150ms**, UI מתעדכן ≤ **500ms**.
* Auto-Execute (Web) → route+place internal ≤ **150ms**; עדכון פוזיציה ≤ **10s**.
* SSE uptime ≥ **99%**, p95 API < **1.6s**, error-rate < **1%**.

---

### Smoke (10 דק׳)

1. בדוק `GET /control/execution-mode` → `TELEGRAM`.
2. הגש כרטיס A+ → Pending; אשר בטלגרם → נכנס/נסגר תקין, באתר read-only.
3. החלף באתר ל-**WEB_AUTO** (Double-Confirm) → כרטיס A+ חדש מבוצע אוטומטית; בטלגרם אין כפתורים.
4. החלפה מהירה הלוך-חזור בתוך 3 שנ׳ → נחסמת (Cooldown).
5. רשומות Audit מוצגות עם IP/nonce/ts/actor.
